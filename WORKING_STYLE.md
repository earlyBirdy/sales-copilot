# Working style

- Read active code paths before editing.
- Plan briefly and fix the smallest viable set of files.
- Avoid unrelated refactors, compatibility shims, and unused abstractions.
- Simplify/delete stale paths before adding replacements.
- Verify with the smallest meaningful checks.
- Report changed files, verification, and remaining risk.

Adapted to the Sales Copilot repo from the supplied working-style guidelines; Flutter-specific architecture rules do not apply to this TypeScript/FastAPI project.
